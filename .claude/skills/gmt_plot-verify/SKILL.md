# GMT 图件布局校验技能

你是一个地学图件排版审阅专家。核心流程：调用 `scripts/verify_plot.py` 脚本，使用 PIL (Pillow) 库对 GMT 生成的图件（PNG/JPG）进行逐项布局检测，输出结构化校验报告。

## 核心设计：计划驱动的检测

**本技能依赖绘图计划（plan.md）来确定图中应该有哪些部件。** plan.md 由上游 `gmt_plot:plan` 技能生成，包含了图件中应有的元素信息（色标、图例、比例尺等）。脚本首先解析 plan.md 提取预期元素，然后**只检测计划中明确提到的元素**，从而避免误判：

| 场景 | 行为 |
|------|------|
| plan 提到色标（位置=右侧） | 优先在右侧搜索色标 |
| plan 提到图例 | 检测图例，未找到则报告 ❌ |
| plan **未**提到图例 | **跳过图例检测**，避免将地图特征误判为图例 |
| plan 提到比例尺 | 检测比例尺 |
| plan 未提到比例尺 | 跳过比例尺检测 |
| 未提供 plan | 检测所有元素（兼容旧行为） |

### 与上游技能的协作

```
gmt_plot:plan  →  生成 plan.md（需求分析、元素设计）
gmt_plot:download/plot  →  使用 plan.md 下载数据、编写脚本
gmt_plot:verify  →  读取 plan.md，理解预期元素，精确检测
gmt_plot:polish  →  根据校验报告修改代码
```

## 设计理念

与 `gmt_plot:compare`（依赖视觉模型做整体质量评估）不同，本技能使用 **程序化图像分析** 对图件布局做精确的像素级检测。视觉模型虽然擅长整体审美判断，但难以精确量化元素间的距离和重叠情况。本技能填补了这一空白：

| 维度 | gmt_plot:compare | gmt_plot:verify |
|------|-----------------|-----------------|
| 检测方式 | 视觉模型（AI） | PIL 程序化分析 |
| 擅长领域 | 整体审美、内容一致性 | 像素级精确测量 |
| 间距检测 | 模糊判断 | 精确到像素 |
| 重叠检测 | 可能遗漏 | 精确识别 |
| 执行速度 | 较慢（API 调用） | 快速（本地计算） |

两者互补：compare 回答"图件好不好看、内容对不对"，verify 回答"元素位置准不准、有没有重叠"。

## 前提条件

1. 确认 PNG/JPG 图件文件已生成且可访问
2. 依赖安装：`pip install opencv-python-headless numpy Pillow`

## 检测项目

脚本对图件进行以下逐项检测（9 个检测步骤）：

### 1. 色标与主图框间距
- 自动识别主图框（最大的矩形边框）和色标条（窄矩形颜色渐变区域）
- 测量两者之间的水平/垂直间距（像素）
- **阈值**：最小 2 像素或图件短边的 0.5%，取较大值
- 检测色标是否与主图框重叠或距离过近
- 同时检测间距是否过大（超过图件短边的 8%）导致视觉松散

### 2. 色标与主图框对齐
- 检测色标条是否与主图框在对应方向上平齐
- 右侧/左侧色标：检查顶部和底部是否对齐图框
- 底部色标：检查左侧和右侧是否对齐图框
- 容许偏差：4% 图框对应维度

### 3. 色标比例检测
- **长度比例**：色标长度应为图框对应维度的 60%-100%，低于 50% 报告偏短
- **宽高比例**：色标应细长，宽高比 > 0.12 时标签文字可能被挤压
- **标签字体**：通过连通域分析估算色标标签文字高度，低于 10px 报告字体过小

### 4. 图例与主图间距
- 自动识别图例框（独立的矩形框，通常含文字和色块）
- 测量图例框与主图框边界的最小距离
- 检测图例是否侵入主图数据区域
- 检测图例是否悬浮在主图中央（距离所有边缘均 > 15% 图框尺寸）

### 5. 图例位置合理性
- 分析主图数据区域的信息密度分布
- 评估图例是否放置在信息稀疏区域（大块同色空白区）
- 检查图例是否靠近至少一个角落（距离 > 35% 对角线为远离角落）
- 检查图例是否遮挡了重要数据特征（如高梯度区域、标注密集区）

### 6. 图例内部元素检测
- **标注-文字间距**：检测图例中色块标识与文字的水平间距，间距 < 4px 为不合格
- **标注形状**：检测颜色标注（色块）宽高比是否过大（> 4.0 为过长/过高的异常形状）
- **列间距**：检测图例中各列之间距离是否过近（< 5px）或过远
- **行间距**：检测图例行与行之间的垂直间距是否过大或过小
- **列间距均匀性**：检测同行中各列间距是否均匀分布

### 7. 图例紧凑度
- 计算图例中前景元素（标识+文字）占图例框总面积的比例
- 内容占比 < 10% 表示背景留白过多，图例不够紧凑

### 8. 元素越界检测
- 检查所有可见元素是否在图件边界内
- 检测标注文字是否被裁切
- 检测色标标签是否完整显示

### 9. 比例尺检测
- 检测图件中的比例尺（交替黑白矩形的窄条）
- 检查比例尺是否覆盖主图框边框

### 10. 标注重叠检测（基础）
- 检测经纬度标注是否与边框线重叠
- 检测标题是否与其他元素重叠
- 检测多个文本标签之间是否相互重叠

## 执行流程

### 第一步：运行 verify_plot.py 脚本

**必须提供 `--plan` 参数**（指向上游 `gmt_plot:plan` 生成的 plan.md），以启用计划驱动的精确检测。

```bash
python3 scripts/verify_plot.py <image_path> --plan plan.md [--output REPORT.md] [--output-dir DIR] [--threshold PIXELS]
```

**参数说明：**
| 参数 | 默认值 | 说明 |
|------|--------|------|
| `image` | （必填） | 待校验的 GMT 图件路径（png/jpg） |
| `--plan plan.md` | **强烈建议** | 绘图计划文件，用于确定预期元素，避免误判 |
| `--output REPORT.md` | `verify_report.md` | 校验报告输出路径 |
| `--output-dir DIR` | `.` | 输出目录 |
| `--threshold PIXELS` | `2` | 最小间距阈值（像素），默认 2px |
| `--ratio FLOAT` | `0.005` | 间距占短边最小比例，默认 0.5% |

**示例：**
```bash
# 推荐用法：附带计划文件
python3 scripts/verify_plot.py ./output.png --plan plan.md --output verify_report.md

# 无计划文件（兼容模式，可能产生更多误判）
python3 scripts/verify_plot.py ./output.png --output verify_report.md
```

### 第二步：脚本行为说明

0. **计划解析**（新增）：解析 plan.md，提取预期元素（色标、图例、比例尺）
1. 使用 OpenCV 加载图件，提取像素数据
2. **主图框检测**（边缘扫描法，针对 GMT 边框位于图件外围的特点）
3. **色标条检测**（梯度分析法 + 颜色递进回退法 + plan 位置引导）
4. **图例框检测**（轮廓拟合法 + 无框图例回退法，按 plan 预期决定是否执行）
5. **信息密度评估**（8×8 网格颜色方差+边缘密度分析）
6. **间距测量**（色标/图例与主图框的像素距离）
7. **色标细节检测**（对齐检测、长度比例、宽高比、标签字体大小）
8. **图例细节检测**（标注-文字间距、标注形状、列间距、行间距、紧凑度、角落贴近度）
9. **比例尺检测**（交替黑白矩形模式匹配 + 边框重叠检查）
10. **重叠与越界检测**（跨行重叠、同行间距、元素越界）
11. **计划交叉验证**（新增）：对比检测结果与 plan 预期，报告缺失或意外的元素

### 第三步：解读校验报告

脚本执行成功后，读取校验报告，重点关注：

- **❌ 不合格项**：必须修复的布局问题（间距不足、元素重叠）
- **⚠️ 需改进项**：建议优化的布局问题（图例位置不佳等）
- **✅ 合格项**：通过检测的项目
- **修改建议**：具体的 GMT 参数调整建议（如 `-X` / `-Y` 偏移量、图例位置参数等）

然后将校验报告的内容告知用户，便于调用 `gmt_plot:polish` 进行针对性修改。

## 校验逻辑详情

### 主图框检测算法（边缘扫描法）

GMT 图件的边框始终位于图像外围，利用这一特点：
1. 对灰度图执行 Canny 边缘检测（低阈值，捕捉细边框线）
2. 从图像顶部向下逐行扫描，找到第一条含长连续边缘像素的行 → 上边框
3. 从底部向上扫描 → 下边框；从左向右 → 左边框；从右向左 → 右边框
4. 若边缘扫描未找到有效边框（如被地质多边形边界干扰），回退到 Hough 线检测 + 密度投影法

### 色标条检测算法（梯度分析法）

1. 在主图框外侧四个方向（右/底/左）搜索
2. 使用 `cv2.Sobel` 计算沿色标长轴方向的梯度强度
3. 色标列应具有中等且连续的梯度（非均匀也非噪声）：梯度归一化值在 0.03~0.85 之间
4. 找到满足条件的最大连续列/行块
5. 根据长度匹配度（色标长度应达图框对应维度的 60-100%）和梯度一致性计算置信度
6. 置信度 < 0.30 的候选被拒绝

### 图例框检测算法（轮廓拟合法）

1. 在主图框内部执行 Canny 边缘检测 + 形态学闭运算连接断裂边缘
2. `cv2.findContours(RETR_EXTERNAL)` 提取外轮廓
3. `cv2.approxPolyDP` 拟合多边形，保留 4-12 顶点的准矩形候选
4. 候选筛选：
   - 面积占主图框 0.5%-30%
   - 宽高比 0.25-4.0
   - 距图框边缘 ≥ 3px
   - 内部平均亮度 ≥ 140（白色/浅色背景）
   - 边框得分：周长上边缘像素覆盖率 ≥ 25%（小候选）或 ≥ 40%（大候选）
5. 综合评分 = 0.25×边框得分 + 0.20×亮度分 + 0.30×内部结构分 + 0.25×矩形度
6. 取最高分候选，得分 > 0.35 视为有效图例

### 图例内部元素分离（连通域分析）

1. 对图例区域执行 Otsu 二值化
2. `cv2.connectedComponentsWithStats` 分离每个前景元素
3. 按面积和宽高比分类：面积 < 800 且宽高比 0.2-3.0 → 标识色块；其余 → 文字区域
4. 按 y 坐标聚类分组（y 中心差 < 8px → 同行）

### 信息密度评估

1. 对主图区域划分为 8×8 网格
2. 每格计算颜色方差（60%）+ Sobel 边缘密度（40%）
3. 归一化到 0-1 范围，0 = 信息稀疏
4. 计算图例所在格的密度百分位
5. 比较四角密度，推荐密度最低的角落

### 重叠检测

1. **跨行重叠**：不同行的标识与文字存在垂直和水平双重重叠 → ❌ 不合格
2. **行间距过小**：相邻行 y 中心间距 < 2px → ❌ 不合格
3. **同行水平重叠**：同行的标识与文字水平重叠率 > 20% → ⚠️ 需改进
   （注：GMT 图例中标识在文字左侧、正常相邻不视为重叠）

## 错误处理

如果脚本执行失败：
1. 确认 `pip install opencv-python-headless numpy Pillow` 已安装
2. 检查图件是否存在且可读
3. 检查图件格式是否支持（PNG/JPG）
4. 如果图件中检测不到主图框（纯图像无边框），脚本会尝试使用整图作为主图区域并给出提示
5. 如果色标条未检测到，会提示可能不存在色标或色标与主图融合

## 使用限制

1. **仅适用于 GMT 标准布局**：主图框 + 色标条 + 可选图例的标准排版
2. **多子图支持有限**：当前版本主要针对单幅主图，多子图场景可能检测不完整
3. **非标准布局**：如果图件采用非标准布局（如色标在底部、图例在主图外等），部分检测可能不准确
4. **分辨率要求**：建议图件分辨率不低于 300x300 像素，过低分辨率会影响检测精度
5. **边框要求**：图件应有可见的边框线，否则主图框检测可能失败
6. **内嵌色标限制**：部分内嵌于图框内部的色标条可能无法被检测到（特别是离散色块型色标）
7. **指南针等装饰元素**：当前版本不检测指南针、指北针等装饰元素的位置合理性
8. **字体大小估算**：色标标签字体大小通过连通域分析估算，实际字体可能略有偏差
